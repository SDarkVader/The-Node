# Experiment scope, evidence and development

Updated 2026-10-23. Start with the [current experiment](research/CURRENT_EXPERIMENT.md).
Present implementation, recorded evidence and further work are distinct from the programme's
eventual scope. Unimplemented work is not a limitation on what the experiment may become.

## Recorded evidence and evaluation responsibilities

The current live work studies reasoning continuity in an evolving Node world. Two Bakers
completed 36 decisions over 18 ticks, retaining their own earlier conversation while the
authorized world view and diary changed. The run is stopped at a verified checkpoint.

The record demonstrates accepted live continuation, exact client-side history preservation,
recognition/diary behaviour, actual diary expiry, accounting order and independent replay.
Whether transcript memory improves decisions, or which earlier thought caused an action,
remains a question for further experiments. No matched comparison was run; stopping was
exploratory. Those facts govern claims about this record, not the programme's future.

Keep proposals, validator-admitted actions and kernel effects distinct. A legal diary impression
is not proof of its factual accuracy. Returned thinking summaries are partial evidence, not a
complete account of internal reasoning. Stable prices, diary choices or wealth changes alone
do not establish cooperation, deception, motive or causal welfare effects.

Assess an actor using information legitimately received at the time. An earlier diary exposure
is historical, not current recognition or permission. Protocol/infrastructure failures need
their own outcomes; unknown usage keeps its hold. Fixture-agreement counts test fixture/scorer
implementation, not additional live-model behaviour. Retain their source revisions.

## Evaluation ownership and separation

The run operator records requests, returned reasoning, decisions, receipts, validation and kernel
outcomes. It may comment on what returned reasoning says, clearly attributed as a comment; it
must not simultaneously improvise an evaluation or grade that reasoning or decision quality.

Interpretation belongs to a named evaluation framework/scorer or a human reviewer. If an assistant
runs an evaluation itself, identify the specific metric, definition, evidence inputs and result;
keep that evaluation separate from execution and from freeform reasoning comments. Do not turn
a comment, an exploratory stopping label, schema acceptance or a replay check into a quality score.

Inspect imported the continuation records; no reasoning-quality score or causal memory evaluation
was produced for this pilot. The original offline scorers have explicit rules for their own
fixtures; their scores must not be presented as grades of this live continuation run.

## Implementation and configuration

Live calls use explicitly accounted TypeScript runners. The original Inspect solver selects
offline `mockllm`; Inspect also imports verified continuation exports without provider calls.
The original production broker's protected live gate remains unchanged. The separate paused
authority-attribution study retains its frozen manifest and current-view memory condition.

The extension's actors, model, 2,048 output cap, 95,000-byte request profile, 100-request
allowance and USD 1 ceiling describe that run. They are revisable engineering and experimental
choices. A future change needs the relevant implementation, tests, provenance and authorization;
it is not evidence that the programme has reached a fundamental limit.

Recognition v2, individual dealings and v2 Grifter speech/diary permissions are implemented.
The implemented [A01 diary contract](research/DIARY_CONTRACT_A01.md) permits authored menu
entries. Automatic event-only marking was an earlier design; it is not the implemented contract.
Complete restricted trespass and individual abode transactions remain development work.

AgentDojo and ControlArena inform adapted task/oversight patterns. Their native packages and
Concordia are not integrated. Deterministic scorers and monitors exist; additional framework
and model-based analysis is work to select and build. NIST AI RMF mappings are project-defined
with illustrative thresholds, not certification.

## Further work

Memory-condition comparisons, transcript bounds/degradation, mechanics-grounded interpretation
checks, broader roles/seeds/horizons, gameplay transactions and selected framework integrations
are implementation or research tasks. State each task, the evidence needed and the next
acceptance check. Do not recast missing work as a constraint on the experiment's eventual scope.

Reserve *limitation* for a boundary that cannot be crossed under explicit conditions, and explain
why. Private files cannot be recovered from a Git clone that never contained their bytes;
secure recovery is still developable. A causal effect is not identified by this uncontrolled
record alone; designing and running a comparison is still possible.

## Recovery, privacy and spending

GitHub carries committed source, current documentation and sanitized evidence. Private responses,
signatures, observations, runtime state, credentials and journals remain private. A fresh session
reads [CURRENT_SESSION](recovery/CURRENT_SESSION.md), verifies Git state and, where needed,
obtains and verifies the actual private evidence. It must not invent missing records, reset
balances or repeat calls. Documentation does not dispatch runs or authorize a new allowance.
